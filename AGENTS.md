## Цель

Создать аккуратный адаптивный одностраничный веб-прототип витрины туристских поездов по данным из `trains.json` (JSON с 5 поездами). Решение — тестовое задание Центра развития туризма АО «ФПК».

## Обязательная функциональность

- На главном экране показать список поездов карточками.
- В карточке списка вывести: название, регион, маршрут в формате «первый город → последний город», длительность, ближайшую дату отправления и цену «от».
- Реализовать фильтр по региону.
- Реализовать фильтр по месяцу отправления.
- Реализовать поиск по названию поезда.
- По клику на поезд открывать его подробную карточку.
- В подробном представлении показать: полное описание, все даты отправления, список экскурсий и теги.
- Кнопка «Купить билет» должна открывать внешний `buy_url` в новой вкладке.
- Интерфейс должен корректно и приятно выглядеть как на телефоне, так и на компьютере.

## Ограничения и технические ориентиры

- Стек и библиотеки можно выбирать свободно; при выборе ценить простоту запуска, читаемость и уместность для небольшого одностраничного прототипа.
- Бэкенд, авторизация, база данных и реальная покупка не нужны.
- Данные должны читаться из JSON, а не быть размазаны по компонентам интерфейса.
- Избегать лишней сложности и визуальных излишеств; приоритеты — рабочая функциональность, ясная структура кода и аккуратный UX.
- Фильтры и поиск должны работать совместно; состояния без результатов и отсутствующих данных должны быть обработаны явно.
- Не выдумывать содержимое поездов, если исходные данные доступны или ожидаются: сохранять фактические значения из набора данных.
- Перед проектированием и реализацией интерфейса учитывать постоянный визуальный бриф из `DESIGN_DIRECTION.md`.

## Стек и архитектура

- Next.js 16 с App Router, TypeScript, React, Tailwind CSS и ESLint.
- Использовать Feature-Sliced Design: `app` только для маршрутизации и глобальной композиции, затем `widgets`, `features`, `entities`, `shared`.
- Не создавать FSD-слой `src/pages`, поскольку это имя конфликтует с Pages Router в Next.js; роль страниц выполняют route-файлы `src/app/**/page.tsx`.
- Импорты между слоями вести через публичные `index.ts` и алиас `@/*`; нижние слои не должны импортировать верхние.

## Критерии готовности и сдача

- Все описанные сценарии работают в развёрнутой версии.
- Исходный код опубликован в GitHub или GitLab.
- Есть публичная ссылка на развёрнутую версию (например, GitHub Pages, Vercel или Netlify).
- В репозитории есть README объёмом 5–15 строк: локальный запуск, принятые решения и их причины, а также что улучшить при наличии ещё двух дней.
- Перед сдачей проверить адаптивность, внешние ссылки, все фильтры, поиск и содержимое подробного представления.
